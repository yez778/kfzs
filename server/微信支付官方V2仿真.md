# 微信支付「官方 V2 仿真测试系统」接入说明

本模块对接微信支付**官方 V2 仿真环境**（`sandboxnew`），与默认的本地自建沙箱相互独立：

| 模式 `PAYMENT_MODE` | 是否请求微信 | 报文/签名 | 能否小程序调起收银台 | 用途 |
| --- | --- | --- | --- | --- |
| `sandbox`（默认） | 否 | 本地 HMAC 模拟 | 否（点“模拟支付成功”） | 答辩/课堂演示，一键走通 |
| **`v2sandbox`（本模块）** | **是** | **XML + MD5** | **否**（仿真只验后端） | 真实商户号/密钥的后端报文联调 |
| `wechat`（预留） | 是 | V3 JSON + RSA + AES-GCM | 是 | 正式上线 |

## 前置条件

官方 V2 仿真**仍需真实商户资料**：

1. 已开通微信支付的**真实商户号 `mch_id`**；
2. 商户平台 → API 安全 → 设置的**真实 APIv2 密钥**（32 位）；
3. 一个该公众号/AppID 下的**真实用户 openid**（JSAPI 下单必填）。

学生/演示账号没有商户号时，仿真接口会在 `getsignkey` 阶段返回无权限——这是正常的，请继续用默认 `sandbox` 模式演示。

## 配置

```env
PAYMENT_MODE=v2sandbox
PAYMENT_APPID=wxxxxxxxxxxxxxx        # 真实公众号/小程序 AppID（留空回退 WECHAT_APPID）
PAYMENT_MCH_ID=16xxxxxxxx            # 真实商户号
PAYMENT_API_V2_KEY=xxxxxxxxxxxxxxxx   # 真实 APIv2 密钥（32 位）
PAYMENT_SANDBOX_OPENID=oxxxxxxxxxx    # 该 AppID 下真实测试用户 openid
PAYMENT_NOTIFY_URL=https://你的公网域名/api/v1/payments/notify/wechat/v2
PAYMENT_ORDER_EXPIRE_MINUTES=15
```

> `PAYMENT_MCH_KEY`（本地 HMAC 用）在 v2sandbox 模式下不参与官方请求，可保留默认值。

## 自检（不下单、不扣款）

先验证商户号 + APIv2 密钥能否换到沙箱密钥：

```bash
cd backend
PAYMENT_MODE=v2sandbox \
PAYMENT_MCH_ID=16xxxxxxxx \
PAYMENT_API_V2_KEY=xxxxxxxx \
python -m app.core.payment_v2
# [OK] getsignkey 成功，沙箱密钥 sandbox_signkey=xxxx
```

实现位于 `app/core/payment_v2.py`：
- `get_sandbox_sign_key()` → `POST /sandboxnew/pay/getsignkey`（用**真实 APIv2 密钥**做 MD5 签名）
- 换到的 `sandbox_signkey` 在进程内缓存，后续下单/查单/关单/通知都用它签名。

## 链路（与本地沙箱共用同一套订单/库存逻辑）

```
POST /shop/checkout
   本地落 unpaid 订单 + 原子预占库存 + 支付单(prepay_id=pending)
   → 官方 sandboxnew/pay/unifiedorder（MD5 签名）
   → 成功回填沙箱 prepay_id，返回 V2 风格 JSAPI 参数（signType=MD5）
   → 网关失败则自动关单、归还预占库存

POST /payments/sandbox/complete
   v2sandbox 模式下不再“伪造成功”，改为官方 sandboxnew/pay/orderquery 查真实 trade_state：
     SUCCESS → 幂等履约（订单 paid）
     NOTPAY/USERPAYING/... → 原样返回，不改状态

POST /payments/by-order/{id}/close
   先官方 sandboxnew/pay/closeorder，再本地取消并归还库存

POST /payments/notify/wechat/v2   （原始 XML，验 MD5）
   官方支付结果通知：验签 + 金额核对 → 幂等履约；返回也必须是 XML
```

> 重要：官方仿真的 JSAPI 支付**没有“模拟用户付款成功”的触发入口**，因此下单后 `orderquery`
> 通常仍是 `NOTPAY`。仿真环境主要用于验证下单报文/签名、查单、关单、通知验签等后端逻辑；
> 需要“一键支付成功”的演示请用默认 `sandbox` 模式。

## 安全说明

- XML 解析使用一层标签正则提取（不加载 DOCTYPE/外部实体），规避 XXE；
- 沙箱密钥仅存内存缓存，不落库、不写日志（日志只打印 mch_id）；
- 真实 APIv2 密钥只通过环境变量注入，不入库；
- 该模块仅用于联调，**不要**作为正式上线路径——上线请用微信支付 V3。

## 已切换为默认支付模式（最新）

`server/.env` 默认已是：

```
PAYMENT_MODE=v2sandbox
```

### 三步接入（填真实值后即可联调）

| 变量 | 取值来源 |
|---|---|
| `PAYMENT_APPID` | 小程序 AppID（留空回退 `WECHAT_APPID`） |
| `PAYMENT_MCH_ID` | 微信支付商户号（**不能用 1900000000 占位**） |
| `PAYMENT_API_V2_KEY` | 商户平台 → 账户中心 → API安全 → APIv2 密钥（32 位） |
| `PAYMENT_SANDBOX_OPENID` | 一个真实小程序用户 openid（仿真统一下单必填） |
| `PAYMENT_NOTIFY_URL` | 可选，异步通知地址（内网穿透/部署域名） |

配置完成后可用诊断接口自查：

```bash
# 管理员登录拿 token 后
curl -H "Authorization: Bearer <token>" http://127.0.0.1:8000/api/v1/payments/config
```

返回 `ready: true` 且 `issues: []` 表示配置完整；否则按 `issues` 逐项补齐。

### 支付链路（V2 沙箱）

```
小程序下单 POST /shop/checkout
  → 后端落库待支付订单 + 支付单（预占库存）
  → 调 sandboxnew/pay/getsignkey（用真实商户号+APIv2密钥换沙箱密钥，自动缓存）
  → 调 sandboxnew/pay/unifiedorder 拿 prepay_id
  → 返回 pay_params（appId/timeStamp/nonceStr/package/signType=MD5/paySign）
小程序收银台
  → wx.requestPayment 调起微信收银台（V2 沙箱环境）
  → 支付结果以 orderquery 为准（POST /payments/prepay 再 GET /payments/by-order/{id} 同步）
  → 不提供“模拟支付成功”入口，避免伪造支付
异常处理
  → 统一下单失败：自动关单并归还预占库存，返回明确缺失项提示
  → 超时未支付：Celery/懒过期关单（sandboxnew/pay/closeorder）
```

### 只想纯演示（无真实商户凭证）

改回本地沙箱即可（可一键模拟成功/支付中/失败，不触达微信）：

```
PAYMENT_MODE=sandbox
```

### 小程序端行为差异

收银台页按后端返回的 `pay_mode` 自动切换：

- `sandbox`：显示「模拟支付成功 / 支付中 / 失败」三个按钮
- `v2sandbox` / `wechat`：显示「💳 调起微信支付」+「🔍 查询支付结果」，并展示 prepay_id
