# 微信支付（沙箱）接入说明

本模块用**沙箱**完整模拟真实微信支付 JSAPI 的下单/支付/回调生命周期，不真正扣款。
目标是让前端、订单、库存逻辑都按真实时序跑通；将来接真实微信支付时，只需把"网关调用 + 验签/解密"替换为微信支付 v3，业务履约逻辑（`fulfill_payment_success`）可直接复用。

## 与真实微信支付的对应关系

| 真实微信支付 | 本沙箱实现 |
| --- | --- |
| 商户订单号 `out_trade_no`（纯数字字母） | `payment_orders.out_trade_no`，时间戳+随机串 |
| 展示给用户的商城订单号 | `orders.order_id`，如 `2026.10.29.10.44.17` |
| 统一下单返回 `prepay_id` | 沙箱生成 `wx` 开头模拟值 |
| `wx.requestPayment` 的 JSAPI 参数 | `POST /api/v1/payments/prepay` 返回 `timeStamp/nonceStr/package/paySign` |
| `paySign`（商户私钥 RSA-SHA256） | 沙箱用 `PAYMENT_MCH_KEY` 做 **HMAC-SHA256**（签名串结构与微信一致） |
| 微信支付订单号 `transaction_id` | 沙箱生成 `4200` 开头模拟值 |
| 微信服务器支付结果通知（平台证书验签 + AES-GCM） | `POST /api/v1/payments/notify/wechat`，HMAC 签名明文报文 |
| 关闭订单 | `POST /api/v1/payments/by-order/{order_id}/close` |
| 订单超时关闭 | 懒过期（查询时）+ Celery 定时任务 `tasks.sweep_expired_payments` |

## 时序（关键：先支付、后履约）

```
前端                     后端                     库存/订单
 │  POST /shop/checkout   │                         │
 │ ─────────────────────► │ 原子预占库存(UPDATE 行条件)
 │                        │ 建订单 status=unpaid     │
 │                        │ 建支付单 NOTPAY          │
 │  ◄──── JSAPI 参数 ──── │                         │
 │                        │                         │
 │  沙箱收银台点“支付成功”  │                         │
 │  POST /payments/sandbox/complete {result:SUCCESS}│
 │ ─────────────────────► │ fulfill_payment_success │
 │                        │ 幂等：订单 paid / 支付单 SUCCESS
 │  ◄──── paid ────────── │                         │
```

- **下单即预占库存**（`UPDATE product_inventory SET stock=stock-qty WHERE sku_id=? AND stock>=qty`，靠数据库行条件防超卖）；
- **支付成功才置 `paid`**；不扣虚拟钱包（微信支付与钱包余额是两套概念）；
- **取消 / 超时**：归还预占库存，订单 `cancelled`、支付单 `CLOSED`；
- 履约函数对重复通知**幂等**（同一 `out_trade_no` 多次成功回调只生效一次）。

## HTTP 接口（均在 `/api/v1` 下）

| 方法 | 路径 | 鉴权 | 说明 |
| --- | --- | --- | --- |
| POST | `/shop/checkout` | 用户 | 下单，返回待支付订单 + `out_trade_no` + `pay_params` |
| POST | `/payments/prepay` | 用户 | 统一下单，再次取 JSAPI 参数 |
| POST | `/payments/sandbox/complete` | 用户 | **沙箱专用**，模拟收银台结果 `SUCCESS` / `USERPAYING` / `PAYERROR`（可带 `fail_reason`，如 `NOTENOUGH`） |
| GET  | `/payments/by-order/{order_id}` | 用户 | 按商城订单号查支付状态 |
| POST | `/payments/by-order/{order_id}/close` | 用户 | 关闭待支付订单并释放库存 |
| POST | `/payments/notify/wechat` | 签名 | 模拟微信异步通知（外部回调/压测用） |

`/payments/sandbox/complete` 与 `/payments/notify/wechat` 最终都调用同一个幂等履约函数。

三种沙箱结果（演示异常分支）：
- `SUCCESS`：支付成功，订单 `paid`；
- `USERPAYING`：用户仍在输密码/支付中，支付单保持 `NOTPAY`、订单仍 `unpaid`，可稍后再查；
- `PAYERROR`：支付失败（如 `fail_reason=NOTENOUGH` 零钱余额不足），订单仍 `unpaid`，**同一支付单可稍后重试成功**，不重复预占库存。

### 回调签名

```
signature = HMAC_SHA256(PAYMENT_MCH_KEY, f"{out_trade_no}:{transaction_id}:{amount_fen}:SUCCESS")
```

真实接入时把 `wechat_notify` 内的 HMAC 校验替换为：微信平台证书验签 + AES-256-GCM 解密 `resource`，
金额校验与 `fulfill_payment_success(...)` 保持不变即可。

## 配置（环境变量）

```
PAYMENT_ENABLED=true
PAYMENT_MODE=sandbox            # 接真实微信时改 wechat
PAYMENT_APPID=                  # 留空回退 WECHAT_APPID
PAYMENT_MCH_ID=1900000000       # 真实环境填商户号
PAYMENT_MCH_KEY=sandbox-mch-key-change-me   # 生产必须用强随机密钥
PAYMENT_NOTIFY_URL=             # 真实异步回调 https 地址
PAYMENT_ORDER_EXPIRE_MINUTES=15
```

## 小程序端调用

见 `miniprogram-pay-example.js`：下单 → 真实微信 `wx.requestPayment(pay_params)`（沙箱会失败，
因没有真实商户证书），因此演示/答辩时点"模拟支付成功"走 `/payments/sandbox/complete`；
真机接入真实商户后直接用 `wx.requestPayment`，后端再把 `PAYMENT_MODE` 切到 `wechat` 并替换网关调用。

## 订单状态

完整状态机（支付 + 履约闭环）：

```
unpaid 待支付
  ├─ 支付成功 ─▶ paid 待发货（库存已预占）
  │               ├─ 商家发货 ─▶ shipped 待收货（物流公司+单号+发货时间）
  │               │               └─ 买家确认收货 ─▶ completed 已完成
  │               └─ 后台退款 ─▶ refunded 已退款（回补预占库存）
  └─ 关单/超时 ─▶ cancelled 已取消（回补预占库存）
```

履约接口（均在 `/api/v1` 下）：

| 接口 | 权限 | 说明 |
|---|---|---|
| `POST /admin/orders/{order_id}/ship` | staff/admin | 发货：`{company_code, logistics_code}`，支持 SF/YTO/ZTO/STO/YD/JD/EMS；幂等 |
| `POST /admin/orders/{order_id}/refund` | staff/admin | 退款：`{reason}`，仅 paid/shipped；回补库存；幂等 |
| `POST /orders/{order_id}/receive` | 本人 | 确认收货：仅 shipped → completed；校验订单归属 |
| `GET /shipping/companies` | staff/admin | 物流公司字典 |

所有状态迁移都有前置校验，非法流转返回 409；`completed` 订单不能再退款（退货流程另行实现）。`/auth/me/orders` 会返回 `ship_company/logistics_code/shipped_at/received_at/refund_no` 等履约字段。

原有 `shipped / refunding` 等状态兼容；推荐等下游只统计 `paid/shipped`，未支付订单不会进入购买历史。
